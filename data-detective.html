Title

Data Detective: Your Research Data Management Assistant

An AI assistant built on Mizou that walks students and researchers through checking a dataset before analysis. It finds missing-value codes, groups inconsistent labels, helps write a data dictionary and README, and finishes with a cleaning plan. I tested it on a molecular interaction dataset (three-body energies in kcal/mol) with deliberate errors planted in it.

Objective

In my PhD research, the hardest part of machine learning was not the model but the data. Small problems quietly produce wrong answers: "Cl" and "Cl " counted as two different groups, or a missing-value code like -999 averaged in as a real energy. Many early-career researchers never get formal training in catching these problems, and few have a data specialist to ask.

My goal was to build an assistant that catches these problems early and teaches good habits, while keeping the researcher in control of every change to their data.

Process

I followed the design thinking process from empathy to testing:

  1. Empathize: created three user personas (a first-year graduate student, an undergraduate research assistant, and a principal investigator) and listed their pain points, from mixed missing-value codes to undocumented files left behind when students graduate.
  2. Define: wrote a problem statement and a "How might we" question, then mapped each user need to an AI capability, such as text classification for grouping label variants and code generation for applying fixes to a full file.
  3. Ideate: scored five concepts on impact, feasibility, and user value. I chose a guided review assistant (14 of 15) over an upload-and-auto-clean tool, because automatic cleaning could silently delete data and a chatbot cannot reliably process thousands of rows.
  4. Prototype: wrote the assistant's instructions and rules within Mizou's 1,000-character limit, a welcome message with a privacy reminder, and a seven-step conversation flow.
  5. Test and iterate: ran 12 planned test prompts, one or more for every instruction and rule, against a test dataset with a known answer key. I revised the instructions when the assistant fell short.

The assistant's conversation flow

  • Understand the dataset
  • Inspect structure
  • Check missing values
  • Check labels
  • Document sources
  • Plan the cleaning
  • Summarize next steps
Challenges and solutions
ChallengeSolution
My first two platform choices fell through: Chatbase's free tier was too limited, and OpenAI stopped allowing new custom GPTs on personal accounts in 2026.Moved to Mizou. Because my design, rules, and test data were written independently of any one tool, I moved them over without redoing the work.
Language models can miscount or invent results for data they have not seen.Limited reviews to a pasted sample, required counts to say "in the sample you shared," and offered code to process the full file accurately.
In early testing, the assistant did not check every column for missing-value codes.Revised the instructions to check every column and to warn that codes like -999 distort averages, then re-tested.
Research data may include sensitive or identifiable information.Added a privacy reminder to the welcome message and a rule never to ask for or repeat sensitive data.
Users might treat the assistant as a statistician.Made interpreting results out of scope, with a referral to an advisor or statistician.

Value
For research labs, universities, and data teams, this project shows that I can take an AI tool from a real user problem to a tested product: define what it should and should not do, build in guardrails for privacy and accuracy, and test it against a known answer before trusting it. Clean, documented data is the foundation of every reliable analysis and machine learning model.
Key insights
  • What an assistant must not do matters as much as what it does. Clear limits made it more honest about what it had and had not checked.
  • An AI tool is only trustworthy when it is tested against an answer you already know.
  • AI platforms change fast, so a design that is not locked into one tool holds up better.
